# SZU 公文通助手

深圳大学[公文通](https://www1.szu.edu.cn/board/)（Board）分类浏览浏览器扩展，支持 **Chrome** / **Edge**。

每天上百条公文通知混在一起 —— 讲座、活动、比赛、教务、科研……很难快速找到自己关心的内容。这个扩展会自动抓取公文、智能分类，还能根据你的学院和课程个性化排序，让真正重要的内容一眼可见。

---

## 痛点

| 问题 | 说明 |
|------|------|
| **信息过载** | 公文通每天发布大量通知，所有类型混排，无法按类别筛选 |
| **缺少预览** | 列表只显示标题，需要逐条点击才能看到正文内容 |
| **无法个性化** | 不能只看自己学院的通知，也无法屏蔽不相关学院的消息 |
| **分类困难** | 很多公文标题模糊，难以一眼判断是否与自己有关 |

---

## 功能

### 1. 一键抓取

点击 **"获取最新"** 按钮，扩展自动抓取公文通首页和全部 6 个分类板块（教务教学、科研动态、党务行政、学生工作、学术讲座、校园生活），无需手动逐页浏览。

> 抓取前会自动检测校园网 SSO 登录状态。如果登录过期，会提示你在浏览器中重新登录 `www1.szu.edu.cn`。

### 2. 智能分类

每条公文自动归入以下 8 个类别之一：

| 类别 | 说明 | 匹配方式 |
|------|------|----------|
| **讲座** | 学术报告、公开课、研讨会、论坛、沙龙 | 关键词 + AI |
| **活动** | 文艺演出、展览、招新、志愿者、运动会、典礼 | 关键词 + AI |
| **比赛** | 竞赛、选拔赛、挑战赛、答辩评比 | 关键词 + 竞赛目录匹配 |
| **教务** | 选课、考试、成绩、毕业、奖学金、四六级 | 关键词 + AI |
| **公示** | 拟推荐名单、拟获奖名单、公示期 | 关键词（优先匹配） |
| **新闻** | 活动回顾、赛事报道、会议总结、成果发表 | 标题关键词 + 正文信号 + 日期检测 |
| **科研** | 项目申报、基金、课题、实验室、博士后 | 关键词 + AI |
| **生活** | 后勤、校园卡、宽带、图书馆、天气提醒 | 关键词 + AI |
| **待分类** | 所有关键词和 AI 都无法判断的公文 | 兜底分类 |

> **新闻**分类采用了三层检测机制：标题关键词（如"成功举办""圆满落幕"）、正文报道用语（如"会上指出""进行了分享"）、日期回溯检测（正文提到早于发布时间的日期）。同时通过 `isForwardLookingNotice` 排除带有"通知""报名""将于"等前瞻性措辞的公文，减少误判。

### 3. AI 增强分类

配置 DeepSeek API Key 后，关键词无法匹配的公文会**自动调用大模型判断类别**：

- 仅处理关键词阶段未命中的"待分类"公文，不浪费 API 调用
- 每篇公文只尝试一次 LLM，不重复请求
- 模型回复格式经过约束（只返回类别名，`temperature=0.1`），结果稳定
- Prompt 中包含每个分类的**详细语义描述和判断规则**，分类准确度远超纯关键词

> 手动重新分类的公文不会被 AI 覆盖。

### 4. 个性化排序

在设置中填写你的学院和课程名称后：

- **相关（黄色高亮置顶）**：与你学院或课程直接相关的公文
- **无关（底部折叠）**：明显属于其他学院的公文，统一折叠在列表底部
- **中性（正常显示）**：无法判断的公文保持原样

学院匹配支持全称和简称别名（如"计算机与软件学院"也能匹配"计软学院"）。

### 5. 内容预览 & 交互

- **单击卡片**：展开/收起公文详情（标题、发布时间、地点、发布单位、摘要前 300 字）
- **长按或右键**：弹出操作菜单（删除 / 重新分类）
- **查看原文**：展开卡片后点击"查看原文 →"，在新标签页打开公文通原始页面
- **搜索**：支持按标题、摘要、发布单位搜索

### 6. 收藏 & 管理

- 点击星标 ☆/★ 收藏重要公文，"收藏"标签页快速查看
- 删除的公文加入黑名单，下次抓取不会重新出现
- 可配置存储时间（1-7 天），超期的非收藏公文自动清理

## 分类流程图

```
抓取公文详情（标题 + 摘要 + 发布日期）
    │
    ├─ ① 公示关键词命中？ ────→ 公示
    │
    ├─ ② 新闻关键词命中？ ────→ 新闻
    │     ├─ 标题关键词（成功举办、圆满落幕、回顾…）
    │     ├─ 正文信号匹配 ≥2（会上指出、进行了分享…）
    │     └─ 日期回溯检测（正文提到早于发布时间的日期）
    │
    ├─ ③ 关键词匹配（讲座/活动/比赛/教务/科研/生活）
    │     └─ 命中？ ────→ 对应类别
    │
    ├─ ④ 未命中 && API Key 已配置？
    │     └─ 调用 LLM 判断 ────→ LLM 分类或 待分类
    │
    └─ ⑤ 否则 ────→ 待分类
```

## 技术架构

```
info-board/
├── modules/                    # 核心模块（与平台无关）
│   ├── types/index.ts          # 类型定义 + BUILTIN_CATEGORIES 硬编码配置
│   ├── classifier/
│   │   ├── keywordMatcher.ts   # 关键词分类 + 新闻检测
│   │   ├── llmClassifier.ts    # DeepSeek API 调用（URL/Model 硬编码）
│   │   └── competitionMatcher.ts # 竞赛目录匹配
│   ├── crawler/
│   │   ├── fetcher.ts          # fetch + GBK 解码 + SSO 检测
│   │   ├── boardParser.ts      # 正则解析公文通 HTML
│   │   └── deduplicator.ts     # URL 去重 + 黑名单
│   └── storage/
│       ├── notices.ts          # 公文 CRUD
│       ├── settings.ts         # 用户设置持久化
│       ├── crawlState.ts       # 抓取状态
│       └── cleanup.ts          # 过期公文清理
├── entrypoints/
│   ├── background/index.ts     # Service Worker（抓取调度 + 消息路由 + 重分类）
│   ├── popup/                  # 扩展弹窗 UI（React）
│   │   ├── App.tsx             # 主组件（状态管理 + 个性化匹配）
│   │   ├── components/         # NoticeList, NoticeCard, Header, SearchBar...
│   │   └── hooks/              # useNotices, useCategories, useCrawlStatus
│   └── options/                # 设置页（独立标签页）
│       ├── App.tsx             # 设置页主组件
│       └── components/
│           └── ApiKeySection.tsx # DeepSeek API Key 配置
├── data/
│   └── competitions.json       # 竞赛目录数据（4600+ 项）
├── wxt.config.ts               # WXT 框架配置
└── package.json
```

**技术栈：** WXT 0.20（Chrome MV3 扩展框架）+ React 19 + TypeScript + Tailwind CSS v4

**关键设计决策：**
- 所有分类关键词**硬编码**在 `BUILTIN_CATEGORIES` 中，不再提供 UI 编辑（简化维护，避免"改了关键词但没生效"的困惑）
- DeepSeek API URL 和 Model **硬编码**（`https://api.deepseek.com/chat/completions` / `deepseek-chat`），用户只需填写 Key
- 始终抓取全部 6 个板块，不提供订阅选择（减少配置负担，信息不遗漏）
- Service Worker 用正则解析 HTML（MV3 无 DOMParser），GBK 编码通过 `TextDecoder` 处理

## 开发指南

### 环境要求

- **Node.js** >= 18
- **pnpm**（推荐，项目使用 pnpm-lock.yaml）

### 安装 & 运行

```bash
# 1. 克隆项目
git clone https://github.com/ChronicleY/InfoBoard.git
cd InfoBoard

# 2. 安装依赖
pnpm install

# 3. 开发模式（自动 watch + 热更新）
pnpm dev        # 默认浏览器
pnpm dev:chrome # Chrome 专用
pnpm dev:edge   # Edge 专用

# 4. 生产构建
pnpm build        # 默认浏览器
pnpm build:chrome # Chrome 专用
pnpm build:edge   # Edge 专用
```

构建产物在 `dist/` 目录下，按浏览器类型分目录（如 `dist/chrome-mv3/`）。

### 加载扩展到浏览器

1. 打开 Chrome/Edge，地址栏输入 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角 **"开发者模式"** 开关
3. 点击 **"加载已解压的扩展"**
4. 选择项目中的 `dist/chrome-mv3` 目录
5. 扩展图标出现在浏览器工具栏，点击即可使用

> 开发模式下也可以直接把 `dist/chrome-mv3` 目录拖到扩展管理页面加载。

### 调试

- **Service Worker**：在 `chrome://extensions` 中找到扩展 → 点击 "Service Worker" 链接 → 打开 DevTools 查看日志
- **Popup**：右键点击扩展图标 → "检查弹出内容"
- **Options 页**：右键点击设置页面 → "检查"

## 使用说明

### 初次使用

1. **登录校园网**：在浏览器中打开 [www1.szu.edu.cn](https://www1.szu.edu.cn)，完成统一身份认证
2. **打开扩展**：点击浏览器工具栏的扩展图标
3. **获取公文**：点击 **"获取最新"** 按钮开始抓取
4. **浏览分类**：通过顶部分类标签切换查看不同类别的公文

### 配置 AI 分类（推荐）

1. 点击右上角齿轮图标进入设置页
2. 在 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建 API Key
3. 将 Key 粘贴到设置页 → 点击"保存" → 点击"测试连接"验证
4. 下次点击"获取最新"时，未命中的公文会自动调用 AI 分类

### 个性化设置

| 设置项 | 说明 |
|--------|------|
| **DeepSeek API Key** | AI 分类必需的 Key，留空则仅使用关键词分类 |
| **我的学院** | 从 28 个学院中选择，相关公文黄色置顶，无关公文底部折叠 |
| **我的课表** | 输入课程名称（每行一个），与课程相关的公文也置顶高亮 |
| **公文存储时间** | 1-7 天，超期的非收藏公文自动清理 |

### 操作技巧

- **重新分类**：长按/右键卡片 → "重新分类" → 选择正确类别。手动分类不会被后续抓取覆盖。
- **搜索**：支持按标题、摘要、发布单位搜索
- **收藏**：点击卡片右侧的 ☆/★ 按钮
- **查看原文**：展开卡片后点击"查看原文 →"

## 修改分类规则

分类关键词硬编码在 [`modules/types/index.ts`](modules/types/index.ts) 的 `BUILTIN_CATEGORIES` 中。如果你需要调整：

1. 编辑该文件中的 `keywords` 数组
2. 运行 `pnpm build` 重新构建
3. 在 `chrome://extensions` 中刷新扩展

**新闻检测**的标题关键词和正文信号在 [`modules/classifier/keywordMatcher.ts`](modules/classifier/keywordMatcher.ts) 中：

- `NEWS_TITLE_KW`：标题关键词列表
- `NEWS_BODY_SIGNALS`：正文信号正则列表
- `matchNewsByDate`：日期回溯检测逻辑
- `isForwardLookingNotice`：前瞻性措辞排除列表

## FAQ

### Q: 点击"获取最新"后没有任何公文？

检查是否已在浏览器中登录 `www1.szu.edu.cn`。扩展依赖你的校园网 SSO 会话（Cookie），如果过期会提示重新登录。可以在校园网环境下打开公文通首页确认登录状态。

### Q: 为什么有些公文仍在"待分类"？

"待分类"意味着关键词和 AI 都无法判断类别。可能原因：
- 未配置 DeepSeek API Key（纯关键词模式覆盖有限）
- 公文内容过于简短或信息不足
- 你可以手动长按卡片 → "重新分类"

### Q: AI 分类会被重复调用吗？

不会。每篇公文 `llmAttempted = true` 后永久跳过。手动重新分类的公文也不会被 AI 覆盖。

### Q: 如何确定一条公文为什么被归入"新闻"？

打开 Service Worker 控制台查看日志，或检查公文的 `matchedKeywords` 字段。新闻匹配有三种来源：标题关键词、正文信号（≥2）、日期回溯。

### Q: 为什么不再支持自定义分类/关键词编辑？

经过多轮迭代发现，手动词编辑容易因为分割符、缓存等问题导致"改了但没生效"。将关键词硬编码在源码中更可靠。如果你需要自定义分类规则，请直接编辑 `BUILTIN_CATEGORIES` 并重新构建。
